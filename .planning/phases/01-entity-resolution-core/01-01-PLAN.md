Create `packages/core/src/entity-resolution/types.ts` with Zod schemas as the single source of truth (following the project's Zod-first pattern from shared/src/).

Define these schemas:

1. **SorRefSchema** — `{ system: string, id: string }` (e.g. `{ system: 'gohighlevel:contact', id: 'abc123' }` or `{ system: 'gmail', id: 'thread:xyz' }`)

2. **EntityAliasSchema** — `{ type: enum('name_variant', 'email_variant', 'sor_id'), value: string, confirmedBy: enum('llm', 'user', 'system'), confirmedAt: string (ISO), confidence: number (0-1) }`

3. **MatchSignalSchema** — `{ field: enum('email', 'sorId', 'name_exact', 'name_fuzzy', 'name_phonetic', 'org_domain', 'llm'), score: number (0-1), weight: number (0-1), detail: optional string }` — For explainability (ERES-06).

4. **EntityIndexEntrySchema** — `{ entityId: string (UUID), name: string, email: optional string, organization: optional string, role: optional string, sorRefs: SorRef[], aliases: EntityAlias[], confidence: number (0-1), lastUpdated: string (ISO), sources: string[] (file paths that contributed) }`

5. **MatchResultSchema** — `{ entity: EntityIndexEntry, confidence: number, tier: enum(1, 2, 3), signals: MatchSignal[], reasoning: optional string }`

6. **EntityIndexSchema** — `{ version: literal(1), entities: EntityIndexEntry[], buildTime: string (ISO) }` — Version field for future migration support.

Export both Zod schemas AND inferred TypeScript types using `z.infer<>`. Example: `export type EntityIndexEntry = z.infer<typeof EntityIndexEntrySchema>`.

Also export a `normalizeEmail` function here (it's a pure utility used by both entity-index and tier1):
- Lowercase the entire email
- For gmail.com/googlemail.com: strip dots from local part, remove +tag, normalize domain to gmail.com
- For all others: remove +tag from local part
- Return normalized string

Also export a `normalizeName` function:
- Lowercase
- Remove punctuation (.,;:!?-_(){}[])
- Collapse whitespace
- Trim
- Sort tokens alphabetically (so "John Smith" == "Smith John")
- Return normalized string

**confidence-scorer.ts:**
Create the confidence scoring engine (ERES-06).

Export `SIGNAL_WEIGHTS` constant:
```
email: 1.0, sorId: 1.0, name_exact: 0.9, name_fuzzy: 0.7, name_phonetic: 0.6, org_domain: 0.6, llm: 0.9
```

Export `calculateConfidence(signals: MatchSignal[]): number` — Compute weighted average: sum(score * weight) / sum(weight). Return 0 if no signals.

Export `createSignal(field, score, detail?): MatchSignal` — Helper that auto-fills weight from SIGNAL_WEIGHTS.

**entity-index.ts:**
Create an `EntityIndex` class (NOT a bare function like knowledge_index.ts — this needs mutation). Follow the JSON persistence pattern from `graph_state.ts`.

Constructor: takes optional `indexPath` (defaults to `path.join(WorkDir, 'entity_index.json')`).

Key methods:
- `load(): void` — Read JSON from disk, validate with EntityIndexSchema, build lookup maps. If file doesn't exist, initialize empty index.
- `save(): void` — Write current state to disk as pretty JSON.
- `getAll(): EntityIndexEntry[]` — Return all entities.
- `findByEmail(email: string): EntityIndexEntry | undefined` — Normalize email, check primary email map AND alias email map. O(1) lookup.
- `findBySorId(system: string, id: string): EntityIndexEntry | undefined` — Check SOR ID map AND alias SOR ID map. O(1) lookup using `${system}:${id}` composite key.
- `findById(entityId: string): EntityIndexEntry | undefined` — O(1) by UUID.
- `addEntity(entry: Omit<EntityIndexEntry, 'entityId' | 'lastUpdated'>): EntityIndexEntry` — Generate UUID (crypto.randomUUID()), set lastUpdated, add to entities array, rebuild maps, return created entry.
- `updateEntity(entityId: string, updates: Partial<EntityIndexEntry>): EntityIndexEntry` — Merge updates, set lastUpdated, rebuild maps, return updated entry.
- `rebuildMaps(): void` — Private method. Build three Maps:
  1. `emailMap: Map<normalizedEmail, EntityIndexEntry>` — includes primary email + all email_variant aliases
  2. `sorIdMap: Map<system:id, EntityIndexEntry>` — includes sorRefs + all sor_id aliases
  3. `idMap: Map<entityId, EntityIndexEntry>`

IMPORTANT: Call `rebuildMaps()` after `load()`, `addEntity()`, `updateEntity()`. Maps are the performance optimization — all lookups go through maps, not array scans.

**tier1-deterministic.ts:**
Create Tier 1 deterministic matching (ERES-01, ERES-02).

Export `tier1Match(candidate: { email?: string; sorId?: { system: string; id: string } }, entityIndex: EntityIndex): MatchResult | null`

Logic:
1. If candidate has sorId: look up via `entityIndex.findBySorId(system, id)`. If found, return MatchResult with confidence 1.0, tier 1, signal `{ field: 'sorId', score: 1.0 }`.
2. If candidate has email: normalize, look up via `entityIndex.findByEmail(email)`. If found, return MatchResult with confidence 1.0, tier 1, signal `{ field: 'email', score: 1.0 }`.
3. If both match the same entity, return with both signals.
4. If both match DIFFERENT entities, return the SOR ID match (SOR ID is authoritative over email — email can be shared/forwarded).
5. If neither matches, return null (escalate to Tier 2).
