Build the fuzzy matching tier, LLM escalation tier, alias persistence, and the 3-tier matcher orchestrator that cascades through deterministic -> fuzzy -> LLM.

Purpose: Tier 2 handles name/org variations without LLM cost. Tier 3 resolves genuinely ambiguous cases with structured reasoning. The alias manager ensures LLM confirmations become future deterministic matches (the learning loop). The matcher orchestrator is the single entry point for all entity resolution.

Output: Complete 3-tier matching pipeline where entities are resolved through increasingly expensive tiers, with LLM decisions persisted as aliases.

**tier2-fuzzy.ts:**

Import `distance` from `fastest-levenshtein`. Import `normalizeEmail`, `normalizeName` from `./types.js`. Import `EntityIndex` from `./entity-index.js`. Import types and `createSignal`, `calculateConfidence` from the local modules.

Export `tier2Match(candidate: { name: string; email?: string; organization?: string }, entityIndex: EntityIndex): { entity: EntityIndexEntry; confidence: number; signals: MatchSignal[] }[]`

Note: tier2Match returns an ARRAY of candidates sorted by descending confidence (the matcher orchestrator decides what to do with them). This is different from tier1 which returns a single match or null.

Logic:
1. For each entity in `entityIndex.getAll()`:
   a. Calculate name similarity:
      - Normalize both names using `normalizeName`
      - If normalized names are identical: score = 1.0, field = 'name_exact'
      - Otherwise: compute Levenshtein distance, normalize to similarity score = 1 - (distance / max(len1, len2))
      - Also compute phonetic similarity: encode both with metaphone (or inline equivalent), compare codes. If codes match: add phonetic signal with score 1.0
      - Skip entity entirely if name similarity < 0.5 (not even close)
   b. Calculate organization similarity (if candidate has organization):
      - Check if any of entity's sorRefs.system contains candidate organization
      - Check if entity's organization field matches (case-insensitive)
      - If match: add org_domain signal with score 1.0
   c. Collect all signals, calculate weighted confidence using `calculateConfidence`
   d. If confidence >= 0.70: add to candidates array

2. Sort candidates by descending confidence
3. Return top 5 candidates (limit to prevent explosion)

**Threshold constants (export for configurability):**
- `FUZZY_MIN_NAME_SIMILARITY = 0.5` — Below this, don't even consider
- `FUZZY_HIGH_CONFIDENCE = 0.85` — Above this, matcher auto-accepts without LLM
- `FUZZY_LOW_CONFIDENCE = 0.70` — Below this, not a candidate at all
- `FUZZY_MAX_CANDIDATES = 5` — Max candidates to return

**tier3-llm.ts:**

Import `generateObject` from `ai` (Vercel AI SDK — already in codebase). Import `z` from `zod`. Import types from `./types.js`.

Define a local Zod schema for the LLM response (NOT exported — internal to this module):
```typescript
const MatchDecisionSchema = z.object({
  decision: z.enum(['same_entity', 'different_entity', 'uncertain']),
  confidence: z.number().min(0).max(1),
  reasoning: z.string(),
  keyFactors: z.array(z.string()),
});
```

Export `tier3LLMMatch(candidate: { name: string; email?: string; organization?: string; role?: string }, topCandidates: Array<{ entity: EntityIndexEntry; confidence: number; signals: MatchSignal[] }>, getModel: () => LanguageModel): Promise<MatchResult | null>`

The `getModel` parameter is a factory function. This keeps tier3-llm.ts decoupled from the model config system. The matcher orchestrator provides it.

Logic:
1. If topCandidates is empty, return null (no match, new entity)
2. Take the top candidate (highest fuzzy confidence)
3. Build a prompt comparing the candidate record against the top existing entity. Include:
   - Both records' fields (name, email, org, role)
   - The fuzzy confidence score and which signals matched
   - Instruction: "Be conservative. If uncertain, say 'uncertain'. Do not guess."
4. Call `generateObject({ model: getModel(), schema: MatchDecisionSchema, prompt })`
5. Map the response:
   - `same_entity` with confidence >= 0.8: Return MatchResult with tier 3, signal `{ field: 'llm', score: result.confidence }`, reasoning from LLM
   - `same_entity` with confidence < 0.8: Still return the match but with lower confidence (the alias manager will decide whether to persist based on confidence)
   - `different_entity`: Return null (new entity)
   - `uncertain`: Return null (conservative — don't merge on uncertainty)
6. Wrap the entire call in try/catch. On LLM failure (network, malformed output, etc.), return null rather than crashing. Log the error.

**alias-manager.ts:**

Import `EntityIndex` from `./entity-index.js`. Import types from `./types.js`.

Export `persistMatchAsAlias(entityIndex: EntityIndex, matchedEntityId: string, candidate: { name?: string; email?: string; sorId?: { system: string; id: string } }, confidence: number): void`

Logic:
1. Find the matched entity by ID
2. If candidate has a name that differs from entity's name (after normalization): add a `name_variant` alias with `confirmedBy: 'llm'`
3. If candidate has an email that differs from entity's primary email (after normalization) AND is not already in aliases: add an `email_variant` alias with `confirmedBy: 'llm'`
4. If candidate has a sorId not already in entity's sorRefs: add the sorRef to the entity
5. Only persist aliases if confidence >= 0.85 (conservative — prevent hallucination persistence, per research pitfall #4)
6. Call `entityIndex.updateEntity()` with the changes
7. Call `entityIndex.save()` to persist to disk

Export `ALIAS_PERSIST_THRESHOLD = 0.85` — configurable constant.

**matcher.ts:**

The 3-tier orchestrator. This is the primary public API.

Import tier1Match, tier2Match, tier3LLMMatch, persistMatchAsAlias, EntityIndex, types.

Export `resolveEntity(candidate: { name: string; email?: string; organization?: string; role?: string; sorId?: { system: string; id: string } }, entityIndex: EntityIndex, options?: { getModel?: () => LanguageModel; skipLLM?: boolean }): Promise<MatchResult | null>`

Logic:
1. **Tier 1: Deterministic** — Call `tier1Match(candidate, entityIndex)`. If match found, return it immediately.
2. **Tier 2: Fuzzy** — Call `tier2Match(candidate, entityIndex)`.
   - If top candidate has confidence >= FUZZY_HIGH_CONFIDENCE (0.85): return it as match (tier 2).
   - If candidates exist but all below 0.85: escalate to Tier 3.
   - If no candidates (all below 0.70): return null (new entity).
3. **Tier 3: LLM** — If `options.skipLLM` is true OR `options.getModel` is undefined, return null (graceful degradation — caller can decide to create new entity). Otherwise call `tier3LLMMatch(candidate, fuzzyResults, options.getModel)`.
   - If LLM confirms match: call `persistMatchAsAlias()` to save aliases, then return the match result.
   - If LLM says no match or uncertain: return null.

Also export `resolveOrCreate(candidate: { name: string; email?: string; organization?: string; role?: string; sorId?: { system: string; id: string } }, entityIndex: EntityIndex, options?: { getModel?: () => LanguageModel; skipLLM?: boolean }): Promise<{ entity: EntityIndexEntry; isNew: boolean; matchResult: MatchResult | null }>`

This is a convenience wrapper:
1. Call `resolveEntity()`. If match, return `{ entity: match.entity, isNew: false, matchResult: match }`.
2. If no match: create new entity via `entityIndex.addEntity(candidate)`, save, return `{ entity: newEntity, isNew: true, matchResult: null }`.
