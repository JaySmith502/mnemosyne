Create `packages/core/src/composio-sync/connectors/gohighlevel.ts`:

This file implements data fetching from GoHighLevel using Composio's `executeAction` function. Each entity type uses the appropriate Composio action slug for the GHL toolkit.

**GHLConnector class:**

Constructor:
- `connectedAccountId: string` — the Composio connected account ID for GHL
- `locationId: string` — the GHL location/sub-account ID (required for all GHL API calls)

Methods:

1. **`async *fetchContacts(since?: Date): AsyncGenerator<Record<string, any>[]>`**
   - Uses Composio action `GOHIGHLEVEL_GET_CONTACTS` (or equivalent — check Composio's tool slugs for GHL contacts listing)
   - Passes `locationId`, `limit: 100`, and `startAfter` (since timestamp) as action input
   - Yields batches of raw contact records (arrays of 100 or fewer)
   - Handles pagination: continue fetching while response contains a next cursor/page token
   - Each batch is yielded as-is (normalization happens upstream in sync engine)
   - Import and use `executeAction` from `'../../composio/client.js'`

2. **`async *fetchOpportunities(since?: Date): AsyncGenerator<Record<string, any>[]>`**
   - Uses Composio action for GHL opportunities search/listing
   - Passes `location_id`, `limit: 100`, pagination params
   - Fields to request (per Claude's discretion for proving pipeline): id, name, pipelineStageId, monetaryValue, status, contactId, createdAt, updatedAt
   - Yields batches of raw opportunity records
   - Paginates via page number (GHL opportunities use page-based pagination)

3. **`async *fetchConversations(since?: Date): AsyncGenerator<Record<string, any>[]>`**
   - Uses Composio action for GHL conversations search
   - **Per user decision:** Only sync last 30 days. If `since` is not provided, default to 30 days ago.
   - Passes `locationId`, `limit: 100`, date filter
   - For each conversation, fetches recent messages using a separate action (limit last 50 messages per conversation)
   - Yields batches of conversation records (each enriched with a `messages` array)

4. **`getEntityFetcher(entityType: string): ((since?: Date) => AsyncGenerator<Record<string, any>[]>) | null`**
   - Returns the appropriate fetch method by entity type name: 'contact' -> fetchContacts, 'opportunity' -> fetchOpportunities, 'conversation' -> fetchConversations
   - Returns null for unknown entity types

**IMPORTANT implementation notes:**
- All Composio `executeAction` calls should be wrapped in the caller's retry logic (not in this class). This class does NOT import retry.ts — that responsibility belongs to the sync engine orchestrator (plan 02-03).
- The Composio action slugs may need adjustment based on actual GHL toolkit action names. Use descriptive slug patterns like `GOHIGHLEVEL_GET_CONTACTS`. The executor should verify actual slugs via `listToolkitTools('gohighlevel')` if needed and document the correct ones.
- Error handling: if an executeAction call returns `{ success: false }`, throw an error with the message. Let the caller (sync engine) decide retry/checkpoint behavior.
- Pagination: for contacts, GHL uses cursor-based (startAfter timestamp). For opportunities, page-number based. For conversations, cursor-based. Check response for `meta.nextCursor`, `meta.total`, or similar fields in the Composio response data.

Create `packages/core/src/composio-sync/writer.ts`:

This file writes synced entities as individual Markdown files and generates manifest.json for observability. Per user decision: "Machine-optimized Markdown files — frontmatter-heavy, minimal formatting, these are pipeline artifacts not user-facing."

**Functions:**

1. **`writeEntityFile(toolkit: string, entity: NormalizedEntity): string`**
   - Import `NormalizedEntity` type from `./types.js`
   - Import `WorkDir` from `../config/config.js`
   - Output directory: `path.join(WorkDir, 'composio_sync', toolkit)`
   - Ensure directory exists (`fs.mkdirSync` recursive)
   - Filename: `{entityType}_{sorId}.md` — sanitize sorId for filesystem safety (replace `/`, `\`, `:`, `*`, `?`, `"`, `<`, `>`, `|` with `_`)
   - File format (frontmatter-heavy):
     ```
     ---
     sorSystem: {entity.sorSystem}
     sorId: {entity.sorId}
     entityType: {entity.entityType}
     syncedAt: {ISO timestamp now}
     {each field from entity.fields as key: value}
     {arrays formatted as YAML lists}
     ---

     # {entity.fields.name || entity.sorId}

     *Synced from {entity.sorSystem} at {syncedAt}*
     ```
   - For YAML frontmatter: use a helper to serialize values properly:
     - Strings: quote if they contain colons or special YAML chars
     - Arrays: format as `\n  - item1\n  - item2`
     - Numbers/booleans: output directly
     - Objects: JSON.stringify as inline value
     - null/undefined: skip field
   - Returns the written filepath

2. **`writeManifest(toolkit: string, manifest: SyncManifest): void`**
   - Import `SyncManifest` type from `./types.js`
   - Writes to `path.join(WorkDir, 'composio_sync', toolkit, 'manifest.json')`
   - JSON.stringify with 2-space indent
   - Ensure directory exists

3. **`readManifest(toolkit: string): SyncManifest | null`**
   - Reads manifest.json for the given toolkit, returns parsed or null if not found
   - Validates with SyncManifestSchema.safeParse

4. **`sanitizeFilename(name: string): string`** (internal helper, not exported)
   - Replaces filesystem-unsafe characters with `_`
   - Truncates to 100 characters

**YAML frontmatter helper notes:**
- Strings containing `:`, `#`, `{`, `}`, `[`, `]`, `,`, `&`, `*`, `?`, `|`, `-`, `<`, `>`, `=`, `!`, `%`, `@`, `` ` ``, `'`, `"` at the start or containing newlines should be wrapped in double quotes with internal double quotes escaped
- Keep it simple — this is machine-consumed output, not human editing. A simple heuristic (quote strings with special chars) is sufficient.
