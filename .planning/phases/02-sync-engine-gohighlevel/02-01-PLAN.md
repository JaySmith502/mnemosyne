Create `packages/core/src/composio-sync/types.ts` with Zod schemas:

1. **FieldMappingSchema** — defines a single field mapping:
   - `source`: `z.union([z.string(), z.array(z.string())])` — source field name(s), supports dot-notation for nested paths (e.g., `"lastMessage.content"`)
   - `required`: `z.boolean().optional()` — whether field is required
   - `transform`: `z.enum(['concat', 'lowercase', 'uppercase', 'trim']).optional()` — transformation to apply
   - `separator`: `z.string().optional()` — separator for concat transform
   - `type`: `z.enum(['string', 'number', 'boolean', 'array']).optional()` — target type
   - `normalize`: `z.enum(['lowercase', 'uppercase', 'email']).optional()` — normalization to apply

2. **EntityConfigSchema** — defines how one entity type maps from SOR to normalized form:
   - `sourceType`: z.string() — the SOR entity type name (e.g., "contacts")
   - `sorSystem`: z.string() — SOR system identifier (e.g., "gohighlevel")
   - `sorIdField`: z.string() — which field is the unique SOR identifier
   - `fields`: z.record(z.string(), FieldMappingSchema) — field mappings
   - `metadata`: z.record(z.string(), z.string()).optional() — metadata field mappings (createdAt, updatedAt)
   - `dateFilter`: z.object({ field: z.string(), lookbackDays: z.number() }).optional() — for time-bounded syncs (conversations)

3. **NormalizerConfigSchema** — top-level config:
   - `toolkit`: z.string()
   - `version`: z.literal(1)
   - `entities`: z.record(z.string(), EntityConfigSchema)

4. **SyncCheckpointSchema** — per-entity-type checkpoint:
   - `toolkit`: z.string()
   - `entityType`: z.string()
   - `lastSyncTime`: z.string() — ISO timestamp
   - `cursor`: z.string().optional() — for cursor-based pagination
   - `lastSuccessfulBatch`: z.number().optional()
   - `consecutiveFailures`: z.number()
   - `lastError`: z.string().optional()

5. **SyncManifestSchema** — per-sync-cycle metadata:
   - `toolkit`: z.string()
   - `syncStartedAt`: z.string()
   - `syncCompletedAt`: z.string()
   - `entities`: z.record(z.string(), z.object({ fetched: z.number(), written: z.number(), errors: z.number() }))
   - `totalFiles`: z.number()
   - `consecutiveFailures`: z.number()

6. **NormalizedEntitySchema** — output of normalization:
   - `entityType`: z.string()
   - `sorSystem`: z.string()
   - `sorId`: z.string()
   - `fields`: z.record(z.string(), z.unknown())
   - `metadata`: z.record(z.string(), z.string()).optional()

Export all schemas AND inferred TypeScript types (e.g., `export type NormalizerConfig = z.infer<typeof NormalizerConfigSchema>`).

Import `z` from 'zod'. Do NOT import SorRef from entity-resolution (keep module self-contained for now; SorRef will be constructed from sorSystem + sorId at integration time in plan 02-03).

Create `packages/core/src/composio-sync/checkpoint.ts`:

**CheckpointManager class:**
- Constructor takes `toolkit: string`, calls `this.load()` on instantiation
- Private `checkpoints: Map<string, SyncCheckpoint>` for in-memory state
- Private `filePath`: computed as `path.join(WorkDir, 'config', 'sync_checkpoints', `${toolkit}.json`)` (import WorkDir from `../config/config.js`)

Methods:
- `load(): void` — reads checkpoint JSON file if exists, populates Map from parsed data. Validates each entry with SyncCheckpointSchema. Silently ignores file-not-found.
- `save(): void` — ensures parent directory exists (`fs.mkdirSync` recursive), serializes Map to JSON with 2-space indent, writes atomically (write to `{filePath}.tmp` then `fs.renameSync` to `filePath`). Import types from `./types.js`.
- `get(entityType: string): SyncCheckpoint | null` — returns checkpoint or null
- `update(entityType: string, updates: Partial<SyncCheckpoint>): void` — merges updates into existing (or creates default with toolkit, entityType, epoch lastSyncTime, 0 consecutiveFailures), saves immediately
- `recordSuccess(entityType: string, cursor?: string): void` — updates lastSyncTime to now ISO, resets consecutiveFailures to 0, clears lastError, optionally sets cursor
- `recordFailure(entityType: string, error: string): void` — increments consecutiveFailures, sets lastError
- `shouldSurface(entityType: string): boolean` — returns true if consecutiveFailures >= 3 (per user decision: "only surface if 3+ consecutive failures")

Create `packages/core/src/composio-sync/retry.ts`:

**RetryOptions interface:**
- `maxAttempts`: number (default 3)
- `initialDelay`: number in ms (default 1000)
- `maxDelay`: number in ms (default 30000)
- `factor`: number (default 2)
- `jitter`: 'none' | 'full' | 'equal' (default 'full')
- `retryableStatusCodes`: number[] (default [429, 500, 502, 503, 504])

**RetryableOperation class:**
- Constructor merges provided options with defaults
- `private calculateDelay(attempt: number): number` — exponential: `min(initialDelay * factor^(attempt-1), maxDelay)`. Jitter: 'full' = `Math.random() * delay`, 'equal' = `delay/2 + Math.random() * delay/2`, 'none' = `delay`
- `async execute<T>(fn: () => Promise<T>): Promise<T>` — loops up to maxAttempts. On error: checks if retryable (status code in list OR error code in ['ETIMEDOUT', 'ECONNRESET', 'ECONNREFUSED']). If retryable and not last attempt, sleeps calculateDelay(attempt) then retries. If 429 and response has Retry-After header (seconds), use that as delay instead. Logs retry attempts with `console.log('[Retry]')`. Non-retryable errors rethrow immediately.

The error checking should handle both standard Error objects and HTTP-like error objects with `response.status` and `response.headers` properties.
