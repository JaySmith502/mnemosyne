Create `packages/core/src/composio-sync/sync-engine.ts`:

This is the heart of the sync pipeline. It orchestrates: load config -> for each entity type -> fetch batches -> normalize -> resolve entity -> write file -> checkpoint.

**Imports:**
- `fs`, `path` from node
- `WorkDir` from `../config/config.js`
- `loadNormalizerConfig`, `normalizeEntity` from `./normalizer.js`
- `CheckpointManager` from `./checkpoint.js`
- `RetryableOperation` from `./retry.js`
- `writeEntityFile`, `writeManifest` from `./writer.js`
- `NormalizerConfig`, `SyncManifest`, `NormalizedEntity` types from `./types.js`
- `EntityIndex`, `resolveOrCreate` from `../entity-resolution/index.js`
- `serviceLogger` from `../services/service_logger.js`
- `GHLConnector` from `./connectors/gohighlevel.js`

**Constants:**
- `SYNC_INTERVAL_MS = 5 * 60 * 1000` — fixed 5-minute interval per user decision
- `CONNECTOR_CONFIG_DIR = path.join(WorkDir, 'config', 'connectors')`

**SyncEngine class:**

Constructor: no arguments needed. State is loaded from config.

Methods:

1. **`getConfiguredConnectors(): string[]`**
   - Scans `~/.rowboat/config/connectors/` for `*.json` files
   - Returns list of toolkit names (filename without extension)
   - Returns empty array if directory doesn't exist

2. **`async syncToolkit(toolkit: string): Promise<void>`**
   - Load normalizer config via `loadNormalizerConfig(toolkit)`
   - Create `CheckpointManager(toolkit)`
   - Create `RetryableOperation({ maxAttempts: 3, jitter: 'full' })`
   - Create entity index: `new EntityIndex(); entityIndex.load();`
   - Initialize connector based on toolkit name:
     - For 'gohighlevel': read `connectedAccountId` and `locationId` from the normalizer config file (add these as top-level fields in NormalizerConfig or read from a separate section). Actually, keep it cleaner: read from `~/.rowboat/config/connectors/gohighlevel.json` which has top-level `connectedAccountId` and `locationId` fields alongside the normalizer config. These are GHL-specific connection params.
     - Create `new GHLConnector(connectedAccountId, locationId)`
   - Start service logger run: `serviceLogger.startRun({ service: 'composio_sync', message: 'Syncing ' + toolkit, trigger: 'timer' })`
   - Initialize manifest: `{ toolkit, syncStartedAt: now, entities: {}, totalFiles: 0, consecutiveFailures: 0 }`

   For each entity type in config.entities:
   - Get fetcher via `connector.getEntityFetcher(entityType)`, skip if null
   - Get last sync time from checkpoint
   - Initialize entity counts: `{ fetched: 0, written: 0, errors: 0 }`
   - Iterate over batches from fetcher (pass `since` from checkpoint):
     - For each raw record in batch:
       - Wrap in retry: `retry.execute(() => { ... })`
       - Normalize: `normalizeEntity(record, entityConfig)`
       - Resolve entity: call `resolveOrCreate` with candidate built from normalized fields:
         - `name`: from normalized fields
         - `email`: from normalized fields (if present)
         - `organization`: from normalized fields (if present)
         - `sorId`: `{ system: entityConfig.sorSystem, id: normalizedEntity.sorId }`
         - Use `{ skipLLM: true }` — per Phase 1 pattern, background processing skips LLM
       - If resolveOrCreate returns entity (new or existing), update entity's SOR refs if the GHL SOR ref is not already present
       - Write entity file: `writeEntityFile(toolkit, normalizedEntity)`
       - Increment written count
     - After each batch: `checkpoint.recordSuccess(entityType)`, increment fetched count
     - On batch error: `checkpoint.recordFailure(entityType, error.message)`, increment errors, continue to next batch (don't abort entire sync)
     - Log progress via serviceLogger

   After all entity types processed:
   - `manifest.syncCompletedAt = now`
   - `manifest.totalFiles = sum of written counts`
   - `writeManifest(toolkit, manifest)`
   - Save entity index
   - Log run_complete via serviceLogger

   **Entity conflict handling per user decision:** "SOR wins — GHL data overwrites when structured data conflicts with existing entity data." When resolveOrCreate returns an existing entity, update its fields from the GHL data (name, email, organization, role) using `entityIndex.updateEntity()`.

   **Archived entity handling per user decision:** "Keep deleted/archived entities as historical data — never delete from graph, mark as archived." If a GHL record has a status indicating deletion/archival (e.g., status: 'lost' for opportunities), still write the file but add `archived: true` to frontmatter. Do NOT delete existing entity files.

3. **`async runOnce(): Promise<void>`**
   - Get configured connectors
   - If none, log "No connectors configured" and return
   - For each toolkit, call `syncToolkit(toolkit)` wrapped in try/catch (one toolkit failure doesn't block others)

**`init()` exported function** (follows pattern from sync_gmail.ts and build_graph.ts):
- Log startup: `'[ComposioSync] Starting sync service...'`
- Interruptible sleep pattern (copy from sync_gmail.ts):
  - `let wakeResolve: (() => void) | null = null;`
  - `export function triggerSync(): void` — wakes the sleep
  - `function interruptibleSleep(ms: number): Promise<void>` — same pattern as Gmail sync
- Main loop: `while(true)` — call `syncEngine.runOnce()`, then `interruptibleSleep(SYNC_INTERVAL_MS)`
- Initial run on startup per user decision: "Auto-start on app launch — if a connector is configured, sync begins immediately"

**NOTE on NormalizerConfig extension:** The `gohighlevel.json` config file needs `connectedAccountId` and `locationId` at the top level alongside `toolkit`, `version`, `entities`. If the NormalizerConfigSchema from Plan 02-01 doesn't have these fields, add them as `.passthrough()` on the schema or add optional fields. The cleaner approach: add `connectionParams: z.record(z.string(), z.string()).optional()` to NormalizerConfigSchema in types.ts. Then GHL config puts `connectedAccountId` and `locationId` inside `connectionParams`.

If types.ts from Plan 02-01 doesn't already have `connectionParams`, add it to NormalizerConfigSchema before implementing sync-engine.
