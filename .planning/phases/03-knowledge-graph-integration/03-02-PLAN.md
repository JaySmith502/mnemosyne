<objective>
Create a deterministic post-processor that ensures every entity note has a correct Sources section derived from its YAML frontmatter, and integrate it into the graph builder pipeline.

Purpose: The LLM agent writes notes with frontmatter and Sources sections per template instructions, but deterministic post-processing guarantees the Sources section always exactly matches the frontmatter sor_refs data. This eliminates any risk of LLM hallucination in source attribution and ensures consistency across all notes.

Output: New note_postprocessor.ts module with frontmatter parsing and Sources generation, integrated into build_graph.ts batch processing.
</objective>

Create a new file `apps/x/packages/core/src/knowledge/note_postprocessor.ts` with the following exports:

**1. `NoteFrontmatter` interface:**
```typescript
interface NoteFrontmatter {
    entity_id?: string;
    sor_refs?: Array<{ system: string; id: string }>;
    entity_type?: string;
    [key: string]: unknown; // Allow other frontmatter fields
}
```

**2. `parseNoteFrontmatter(content: string): NoteFrontmatter | null`**
- Check if content starts with `---\n` (or `---\r\n` for Windows)
- Find the closing `---` delimiter (search for `\n---\n` or `\n---\r\n` starting after the first `---`)
- Extract the YAML text between delimiters
- Parse YAML manually using simple key-value extraction (avoid adding yaml dependency):
  - `entity_id:` → string value
  - `entity_type:` → string value
  - `sor_refs:` → parse the indented array of `- system:` / `id:` pairs
- Return null if no valid frontmatter found
- Handle edge cases: empty frontmatter, malformed YAML, missing fields

**3. `SYSTEM_DISPLAY_NAMES` constant:**
```typescript
const SYSTEM_DISPLAY_NAMES: Record<string, string> = {
    'gohighlevel': 'GoHighLevel',
    'gmail': 'Gmail',
    'calendar': 'Google Calendar',
    'fireflies': 'Fireflies',
    'granola': 'Granola',
    'knowledge': 'Manual Notes',
};
```

**4. `generateSourcesSection(frontmatter: NoteFrontmatter): string`**
- If no sor_refs or empty array, return:
  ```
  ## Sources

  This note is based on knowledge graph sources.
  ```
- Count references per system: `Record<string, number>`
- Sort systems alphabetically
- Generate section:
  ```
  ## Sources

  This note is enriched with data from:

  - **{DisplayName}**: {N} reference(s)
  ```
- Use SYSTEM_DISPLAY_NAMES for display names, fall back to raw system name if not in map

**5. `ensureSourcesSection(content: string): string`**
- Parse frontmatter from content
- If no valid frontmatter, return content unchanged
- Generate the correct Sources section from frontmatter
- If content already has a `## Sources` section:
  - Find `## Sources` and everything after it (up to next `##` heading or end of file)
  - Replace with the generated Sources section
- If content does NOT have a `## Sources` section:
  - Append the generated Sources section at the end (with preceding newline)
- Return the updated content
- IMPORTANT: Preserve all content outside the Sources section — do not modify frontmatter, headings, body, or any other sections

**6. `postProcessBatchNotes(notePaths: string[], workDir: string): { processed: number; errors: number }`**
- For each note path in notePaths:
  - Resolve the full path: `path.join(workDir, notePath)` (note paths from the graph builder are workspace-relative like `knowledge/People/Name.md`)
  - Read the file content
  - Call `ensureSourcesSection(content)`
  - If the content changed, write it back to disk
  - Track processed count and error count
- Return summary stats
- Wrap individual file processing in try/catch — one file error should not stop others
- Log errors with `console.error` for debugging

Import only: `fs` from 'fs', `path` from 'path'. No new dependencies.
